# LibraryInterface

Веб-интерфейс для работы с библиотечной базой данных PostgreSQL. Проект объединяет HTTP API на Go и клиент на Svelte: позволяет искать книги, просматривать доступные экземпляры, подбирать литературу для учебной группы и оформлять выдачу и возврат.

Приложение разрабатывалось как интерфейс к существующей БД. Исходный сервер больше не используется; для полноценного запуска нужна собственная база с совместимой схемой.

## Возможности

- Поиск учебной группы и просмотр списка студентов.
- Подбор книг по специальности и текущему курсу группы.
- Поиск книг по названию без учёта регистра.
- Просмотр карточки книги, общего количества экземпляров и доступных экземпляров.
- Просмотр активных выдач выбранного студента.
- Оформление выдачи и возврата книги.
- Режимы интерфейса для библиотекаря и студента.

Макет, на основе которого создавался интерфейс, находится в [`demo/main.pdf`](demo/main.pdf). Его исходник — [`demo/main.typ`](demo/main.typ).

## Технологии и устройство

**Бэкенд:** Go, стандартный `net/http`, PostgreSQL, `pgx/v5` и пул соединений `pgxpool`. SQL-запросы вынесены в слой репозитория и используют параметры для пользовательских значений.

**Фронтенд:** Svelte 5, TypeScript и Vite. Клиент обращается к API через общий модуль `src/lib/api.ts`.

**Запуск:** Docker и Docker Compose.

```text
backend/
  cmd/server/           # Точка входа HTTP-сервера
  internal/config/      # Настройки из переменных окружения
  internal/db/          # Подключение к PostgreSQL
  internal/httpapi/     # Маршруты, обработчики и CORS
  internal/models/      # Модели данных
  internal/repository/  # SQL-запросы
frontend/
  src/App.svelte        # Основной интерфейс
  src/lib/api.ts        # Клиент HTTP API
demo/                   # Макет интерфейса в PDF и Typst
docker-compose.yaml
.env.example
```

## Запуск через Docker Compose

Нужны Docker с поддержкой Compose и доступная PostgreSQL с совместимой схемой. Compose запускает бэкенд и фронтенд; контейнер PostgreSQL и автоматическое создание схемы в проекте отсутствуют.

1. Создайте `.env` в корне проекта, скопировав `.env.example`:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Укажите в `.env` строку подключения к своей БД:

   ```dotenv
   DATABASE_URL=postgres://example_user:example_password@db-host:5432/example_database
   ALLOWED_ORIGIN=http://localhost:5173
   ```

   Значения в примере вымышлены. Хост должен быть доступен из контейнера бэкенда. `localhost` внутри контейнера указывает на сам контейнер; для PostgreSQL на компьютере с Docker Desktop можно использовать `host.docker.internal`. Специальные символы в логине и пароле строки подключения нужно кодировать как компоненты URL.

3. Из корня проекта выполните:

   ```sh
   docker compose up --build
   ```

После запуска:

- Интерфейс: <http://localhost:5173>.
- API: <http://localhost:8080/api>.
- Проверка HTTP-сервера: <http://localhost:8080/api/health>.

`/api/health` возвращает `{"status":"ok"}` и не проверяет соединение с БД. Фронтенд в текущем Dockerfile запускается через сервер разработки Vite.

Остановка:

```sh
docker compose down
```

## База данных

SQL-запросы используют таблицы `groups`, `students`, `disciplines`, `books`, `bookcopies` и `issuing`. Точные имена столбцов и связи видны в `backend/internal/repository/repository.go`.

В репозитории нет миграций, SQL-скрипта создания схемы и начальных данных. Поэтому пустой PostgreSQL недостаточен для работы приложения. Запросы считают доступными экземпляры со статусом `в наличии`. При выдаче и возврате API меняет записи в `issuing`; согласованное обновление статуса экземпляров должно обеспечиваться базой данных, например триггерами исходной схемы.

## Настройки

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `DATABASE_URL` | Строка подключения бэкенда к PostgreSQL | В Compose обязательна |
| `PORT` | Порт HTTP-сервера | `8080`; задан в Compose |
| `ALLOWED_ORIGIN` | Разрешённый источник запросов браузера | `http://localhost:5173` |
| `VITE_API_BASE_URL` | Адрес API для фронтенда | `http://localhost:8080` |

Корневой `.env` используется Compose для подстановки значений. Go-приложение самостоятельно этот файл не загружает. В текущем Compose адрес API фронтенда задан непосредственно в конфигурации сервиса.

Настоящие данные подключения храните в локальном `.env`, исключённом из Git. В переменные `VITE_*` нельзя помещать пароли и другие секреты: их значения доступны браузеру.

## HTTP API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка HTTP-сервера |
| GET | `/api/groups/{code}` | Данные учебной группы |
| GET | `/api/groups/{code}/students` | Студенты группы |
| GET | `/api/groups/{code}/recommendations` | Подбор литературы для группы |
| GET | `/api/students/{id}/loans` | Активные выдачи студента |
| GET | `/api/books/search?q=...` | Поиск книг по названию |
| GET | `/api/books/{id}` | Карточка книги |
| GET | `/api/books/{id}/copies` | Идентификаторы доступных экземпляров |
| POST | `/api/issuing` | Оформление выдачи |
| PATCH | `/api/issuing/{id}/return` | Оформление возврата |

Тело запроса на выдачу:

```json
{
  "student_id": 1,
  "copy_id": 3
}
```

## Проверки при разработке

Во фронтенде:

```sh
cd frontend
npm ci
npm run check
npm run build
```

В бэкенде, с версией Go, указанной в `go.mod`:

```sh
cd backend
go build ./cmd/server
```

## Текущее состояние

Проект демонстрирует взаимодействие веб-интерфейса с реляционной БД и основные библиотечные операции. Выбор роли переключает экран, но не является аутентификацией или проверкой прав. Кнопка администратора открывает режим библиотекаря; отдельная административная часть пока не реализована.

Для самостоятельного демонстрационного запуска остаётся добавить схему БД и тестовые данные. Для эксплуатации также потребуются аутентификация, проверка прав на сервере и сборка фронтенда для production.
